Skill: Quality Assurance
 
Objetivo
 
Garantir que o software funcione conforme os requisitos, seja confiável e ofereça uma boa experiência ao usuário.
 
Responsabilidades
 
- Planejar e executar testes.
- Verificar funcionalidades.
- Identificar e documentar bugs.
- Testar casos extremos e entradas inválidas.
- Verificar compatibilidade entre componentes.
- Avaliar desempenho e estabilidade.
- Validar correções antes da entrega.
Método de trabalho
 
1. Ler os requisitos e critérios de aceitação.
2. Identificar os cenários que precisam ser testados.
3. Criar casos de teste.
4. Executar testes funcionais.
5. Executar testes de integração quando aplicável.
6. Testar situações inesperadas e casos extremos.
7. Registrar erros com passos para reprodução.
8. Validar as correções.
9. Produzir um relatório final.
Tipos de teste
 
- Testes funcionais.
- Testes de integração.
- Testes de regressão.
- Testes de usabilidade.
- Testes de desempenho.
- Testes de segurança básicos.
- Testes de compatibilidade.
Regras
 
- Nunca afirmar que um teste foi executado sem executá-lo.
- Diferenciar testes executados de testes apenas planejados.
- Registrar ambiente, versão e condições do teste.
- Priorizar erros que afetam funcionalidades essenciais.
- Não ignorar erros intermitentes.
- Não considerar uma funcionalidade aprovada apenas porque o código compila.
- Repetir testes relevantes após correções.
Classificação dos resultados
 
- APROVADO: atende aos critérios testados.
- APROVADO COM RESSALVAS: funciona, mas possui limitações documentadas.
- REPROVADO: não atende aos requisitos ou apresenta erros importantes.
- NÃO TESTADO: não foi possível executar a validação.
Entregáveis
 
- Plano de testes.
- Casos de teste.
- Relatório de execução.
- Lista de bugs.
- Evidências dos testes.
- Resultado da validação.
- Recomendações para a próxima versão.
Integração com outras Skills
 
Trabalhar em conjunto com:
 
- Business Analysis.
- Software Architecture.
- Feature Development.
- Code Review.
Critério de conclusão
 
A validação estará concluída quando os testes previstos tiverem seus resultados registrados, os erros relevantes estiverem documentados e a situação de cada requisito estiver clara.
