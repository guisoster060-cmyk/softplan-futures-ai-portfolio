Skill: Code Review
 
Objetivo
 
Revisar o código-fonte para identificar erros, vulnerabilidades, problemas de desempenho e oportunidades de melhoria.
 
Responsabilidades
 
- Avaliar a qualidade do código.
- Identificar bugs e comportamentos inesperados.
- Verificar segurança e tratamento de dados.
- Identificar duplicações e complexidade desnecessária.
- Verificar compatibilidade com a arquitetura.
- Avaliar legibilidade e manutenção.
- Recomendar correções fundamentadas.
Método de revisão
 
1. Entender o objetivo da alteração.
2. Analisar os arquivos modificados.
3. Comparar a implementação com os requisitos.
4. Verificar possíveis erros e casos extremos.
5. Avaliar segurança e desempenho.
6. Conferir padrões e arquitetura.
7. Classificar os problemas encontrados.
8. Recomendar correções.
9. Fazer nova revisão após as correções.
Classificação dos problemas
 
- CRÍTICO: risco grave de segurança, perda de dados ou falha central.
- ALTO: funcionalidade importante quebrada ou vulnerabilidade relevante.
- MÉDIO: erro localizado ou problema significativo de manutenção.
- BAIXO: melhoria de legibilidade, organização ou estilo.
Regras
 
- Não aprovar código sem analisá-lo.
- Não afirmar que testes passaram sem executá-los.
- Não sugerir mudanças sem explicar o motivo.
- Priorizar problemas reais em vez de preferências pessoais.
- Preservar funcionalidades existentes.
- Não modificar arquivos diretamente durante uma revisão sem autorização.
- Apresentar evidências, arquivos e trechos relevantes.
Entregáveis
 
- Relatório de revisão.
- Lista de problemas classificados.
- Explicação dos riscos.
- Recomendações de correção.
- Resultado da nova revisão.
Integração com outras Skills
 
Trabalhar em conjunto com:
 
- Business Analysis.
- Software Architecture.
- Feature Development.
- Quality Assurance.
Critério de conclusão
 
A revisão estará concluída quando os problemas identificados estiverem documentados, classificados e avaliados, com aprovação ou reprovação justificada.
