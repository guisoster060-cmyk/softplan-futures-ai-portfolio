BUSINESSMIND AI — DEVELOPMENT RULES
 
Versão: 1.0
Status: Regras iniciais de desenvolvimento
 
1. Objetivo
Estabelecer regras obrigatórias para todas as IAs, desenvolvedores e colaboradores envolvidos no BusinessMind AI.
 
O objetivo é garantir organização, qualidade, segurança e consistência durante todo o desenvolvimento.
 
2. Regras gerais
- Trabalhar sempre com base na documentação atualizada.
- Não presumir informações que não foram confirmadas.
- Não tomar decisões importantes sem apresentar justificativas.
- Não criar funcionalidades fora do escopo sem aprovação.
- Priorizar soluções simples, eficientes e sustentáveis.
- Explicar termos técnicos quando necessário.
- Comunicar riscos, limitações e dependências.
3. Arquitetura e tecnologias
- Pesquisar alternativas antes de escolher tecnologias.
- Avaliar custos, desempenho, segurança e escalabilidade.
- Evitar dependências desnecessárias.
- Manter separação adequada entre frontend, backend e banco de dados.
- Documentar decisões arquiteturais.
- Não alterar tecnologias já aprovadas sem justificar os benefícios e impactos.
4. Padrões de código
- Escrever código legível e organizado.
- Utilizar nomes claros para variáveis, funções e arquivos.
- Evitar duplicação de código.
- Separar responsabilidades.
- Tratar erros adequadamente.
- Validar entradas de usuários.
- Criar componentes reutilizáveis quando fizer sentido.
- Manter comentários úteis, sem excesso.
5. Segurança
- Nunca publicar senhas, tokens ou chaves de API.
- Utilizar variáveis de ambiente para informações sensíveis.
- Validar permissões e autenticação.
- Proteger dados empresariais.
- Evitar exposição de informações privadas.
- Utilizar dados fictícios nas demonstrações públicas.
- Considerar boas práticas de proteção de dados e LGPD.
6. Inteligência Artificial
- As respostas da IA devem utilizar dados disponíveis e verificáveis.
- Não inventar indicadores, valores ou conclusões.
- Informar quando não houver dados suficientes.
- Diferenciar fatos, estimativas e recomendações.
- Explicar como as recomendações foram obtidas.
- Avaliar custos, limites e segurança das integrações de IA.
- Evitar enviar dados sensíveis a serviços externos sem autorização.
7. Testes e qualidade
- Testar funcionalidades antes de considerá-las concluídas.
- Criar testes automatizados quando aplicável.
- Verificar erros e casos extremos.
- Testar responsividade.
- Verificar compatibilidade entre módulos.
- Registrar problemas encontrados.
- Não afirmar que testes foram executados quando não foram.
8. GitHub e versionamento
- Utilizar Git para controlar alterações.
- Criar commits com mensagens descritivas.
- Não sobrescrever trabalho funcional sem necessidade.
- Revisar alterações antes de integrar.
- Não enviar arquivos temporários ou segredos.
- Manter README e documentação atualizados.
- Identificar claramente alterações realizadas por agentes de IA.
9. Trabalho entre agentes
Cada agente deverá respeitar sua responsabilidade:
 
Coordenação
 
- Organizar prioridades.
- Distribuir tarefas.
- Aprovar decisões.
- Integrar resultados.
Arquitetura
 
- Definir requisitos.
- Pesquisar tecnologias.
- Planejar estruturas.
- Documentar decisões.
Desenvolvimento
 
- Implementar funcionalidades.
- Seguir a arquitetura aprovada.
- Documentar alterações.
- Informar dependências.
QA
 
- Revisar código.
- Executar testes.
- Identificar falhas.
- Avaliar segurança e qualidade.
Todos devem comunicar conflitos e não modificar decisões de outras áreas sem justificativa.
 
10. Registro de contribuições
Toda contribuição relevante deverá registrar:
 
- Ferramenta ou IA utilizada.
- Objetivo da tarefa.
- Alterações realizadas.
- Arquivos envolvidos.
- Testes executados.
- Resultado da revisão.
- Aprovação ou rejeição humana.
11. Critério para concluir tarefas
Uma tarefa somente poderá ser considerada concluída quando:
 
1. A implementação estiver realizada, quando aplicável.
2. Os testes necessários tiverem sido executados.
3. Os resultados forem verificados.
4. A documentação estiver atualizada.
5. As alterações estiverem registradas no GitHub, quando aplicável.
12. Regra principal
A prioridade não é produzir a maior quantidade de código, mas construir um produto funcional, seguro, compreensível, documentado e tecnicamente consistente.
